## What I learned:

Существуют 2 основных типа форм `Template-driven Forms` и  `Reactive Forms`

`Template-driven Forms` - формы, в которых логика и состояния опретелеяются в темплейте, т.е. в HTML. Такие формы можно использвать для каких-то простых форм, но сейчас используются редко. Они сложнее в тестировании, не подходят для сложных динамических форм. Двусторонняя связь через `[(ngModel)]`

`Reactive Forms` - формы, в которых логика и состяния определяются в классе компонента,  в TS. Такие формы более гибкие, проще тестируются, можно сложнее настраивать логику / валидацию, можно настроить типизацию

Но в новой версии Angular появились также новые виды форм `Signal Forms` - новый подход на основе Signals, который упрощает Reactive Forms. Реактивоность в таких формах под капотом.

реактивные формы монжо создавать через `FormBuilder` - это синтаксический сахар который дает доп возможности например добавить `nonNable`и также состоит из 3х основных блоков
Это три основных блока для работы с Reactive Forms:

`FormControl` - создание, обработка и валидация отдельного поля (одно значение)
`FormGroup` - группа полей (несколько значений)
`FormArray` - массив полей. Динамический список FormGroup'ов или FormControl'ов

Все они имеют методы: get(), value, valid, invalid, reset(), disable(), enable()

У FormControl есть такие свойства как:

value — текущее значение
valid / invalid — валидно ли
touched / untouched — был ли фокус
dirty / pristine — был ли изменён пользователем
errors — объект ошибок валидации
disabled — отключено ли поле

Ключевые методы FormArray:

push() — добавить элемент
removeAt(index) — удалить по индексу
insert(index, control) — вставить в конкретное место
clear() — удалить все
length — количество элементов

```
// Пример создания строго типизированной формы через FormBuilder

this.loginForm = this.fb.nonNullable.group({
  username: ['' , [Validators.required]],
  password: ['' , [Validators.required]]
});

onSubmit() {
  if (this.loginForm.valid) {
    const formData = this.loginForm.getRawValue(); // Забираем все данные, включая disabled поля
    this.authService.login(formData).subscribe();
  }
}
```

### Дополнительно по разделу Components & Signals:

`ViewEncapsulation`: Разница между Emulated (дефолтная изоляция через добавление уникальных атрибутов _ngcontent), None (стили глобальные) и ShadowDom (нативная изоляция браузера).

Свойство `host`: Официальный Angular Style Guide рекомендует использовать свойство host в декораторе @Component для биндинга классов, стилей и прослушивания событий на хост-элементе (вместо `@HostBinding`/`@HostListener`).

`resource` и `rxResource`: Новое API для асинхронного дата-фетчинга. Если меняется сигнал-аргумент (например, catId), ресурс автоматически перезапускает запрос к серверу без RxJS-костылей. resource работает с промисами/fetch, а rxResource — с HttpClient.

### Дополнительно по Modules

`@NgModule` - декоратор, который объединяет связанную функциональность приложения. В классическом Angular модуль определяет область видимости компонентов, директив и пайпов.

Основные метаданные:

`declarations` - компоненты, директивы и пайпы, принадлежащие модулю.
`imports` - подключение других модулей.
`exports` - делает сущности доступными другим модулям.
`providers` - регистрация зависимостей.
`bootstrap` - точка входа приложения (AppModule).

Один компонент может находиться только в одном N`gModule`.
Чтобы использовать компонент в другом модуле, необходимо экспортировать его через `exports`, а затем импортировать сам модуль.

### Дополнительно по Dependency Injection
Иерархия Injector

Angular ищет зависимость по следующей цепочке:
```
Current Element Injector
        ↓
Parent Element Injector
        ↓
Environment Injector
        ↓
Root Injector
```
Побеждает ближайший provider.
